## Mandatory explicit denials

- Deny every action outside the selected allowlist (STS identity retrieval is the non-grant exception). This excludes IAM mutation, S3 security mutation, foundation deletion and deferred services.
- Deny allowed actions outside their exact reviewed resources. S3 ARNs have no account field; wrong bucket ownership is explicitly denied.
- Deny wrong regional endpoints for non-IAM actions, and wrong/missing iam:PassedToService for the Glue role.
- Explicit denies also apply to additional identity policies or same-account session resource-policy grants. Do not omit a shard.
- IAM/global metadata calls remain account/principal/resource scoped without a regional condition.

## API-name differences and dependent permissions

- HeadBucket and bucket-region discovery require s3:ListBucket. The pinned S3 data source also probes GetBucketWebsite; this is read-only, not permission to enable hosting.
- GetBucketEncryption uses s3:GetEncryptionConfiguration. ListObjectVersions uses s3:ListBucketVersions; ListMultipartUploads uses s3:ListBucketMultipartUploads.
- Versioned DeleteObjects requires s3:DeleteObjectVersion; no governance-bypass permission is granted. Cleanup rejects older run IDs before deletion.
- IAM GetRole, named inline policy inventory/read and exact boundary GetPolicy/GetPolicyVersion are read-only. No ListRoles, account policy scan, CreateRole, PutRolePolicy, trust/boundary/managed-policy mutation is included.
- Glue database/table authorization includes the selected catalog and database ancestors. DeleteDatabase requires child table/userDefinedFunction wildcards only inside this dedicated database.
- Athena query APIs restrict workgroup, not arbitrary SQL text; scoped S3 results/data and Glue metadata reads remain dependent permissions.
- Log-group Create/Retention/Delete ARNs include :*; tag APIs use the exact ARN without that suffix. DescribeLogGroups is the only operator Resource * Allow and is read-only.
- Execution role receives only current-run S3 objects, exact bucket list/location and streams of two pre-created log groups. Its immutable boundary explicitly denies every other action and out-of-scope resources.

## Remaining risks and validation limits

The operator can update this job/workgroup/code and change configured worker/time/scan settings through their management APIs. The runner verifies bounds and input hashes before workloads, but IAM cannot freeze every API field, prevent repeated approved calls, cap dollars, or prove synthetic business-result integrity. The owner must review each saved plan/run.

The fixed Glue trust retains SourceAccount and regional Glue SourceArn. Actual service propagation is unverified. Account/SCP/RCP/session policies, Lake Formation controls and service availability were not queried. Owner policy/bucket changes invalidate verification and require separate review.

No Glue security-configuration/log-delivery regional mutation is needed. Lambda/API Gateway/Redshift/EC2/RDS are excluded. No live IAM simulator or Access Analyzer operation was run.
