## Design and preserved behavior

The supplied current-response screenshot was reviewed before changing the UI.
It showed the business value buried in a wide technical paragraph, an oversized
provider banner, weak hierarchy and repeated provenance in the main answer.
The new layout separates the sentence, metric, period, filters, compact source,
grounding and provider status. Complete diagnostics remain expandable.

The user's subsequent ElevenLabs reference informed the final neutral palette,
lighter headline weight, system sans-serif stack, thin borders and restrained
colors. The public reference was inspected directly. No proprietary font or
ElevenLabs asset was copied into the app; the reference screenshot remains local
and ignored. Light mode uses warm neutral surfaces; dark mode uses charcoal.
Charts, forms, cards, chat, tables, tabs and details share the selected theme.

English/Spanish copy and reviewed source translations are centralized under
`src/retailpulse/ui/i18n.py`. Language and theme persist in session state; neither
updates global Streamlit settings. Dates, numbers, axes and tooltips are localized.
Existing filters and stored typed answers survive switching; the language switch
does not make another model call. User-entered question text is retained verbatim.

KPI, forecast and documentation views consume `Answer.result`. No numerical
explanation is generated by a model or parsed from the old formatted answer.
Unknown revenue and undefined scores remain unknown. Refusals, clarifications,
unavailable results and fallback are visibly distinguished from grounded success.
Original repository excerpts and advanced contract fields remain in English;
source quotations are labeled and never given invented translations or citations.

Only a small API boundary normalizer was added: full-string Spanish forms map
onto existing English router inputs. It covers explicit store/month or ISO-date
units, test LightGBM WMAPE/comparison, revenue_proxy definitions and freshness.
Unrecognized suffixes, hidden controls and unsafe content stay subject to the
unchanged RP-09 preflight and scope validation. English requests pass through
unchanged. This is bounded Spanish support, not unrestricted multilingual chat.

Gold, canonical definitions, historical backtests, frozen artifacts, tool
allowlists, grounding and real/synthetic isolation are unchanged. No dependencies,
model downloads or paid services were added.


After validation, the temporary instance stopped and ports 8002/8503 closed.

Restart that existing demo to load the updated API language normalization and UI.

The browser script tests all four pages, changes language/theme within one
session, verifies a live Spanish Ollama answer and the same answer in English,
checks an independent session's defaults, and inspects a 760-pixel layout.
It waits for rendering to finish, rejects clipped KPI values and asserts dark
input text, background and selector-button colors. Caption opacity is checked
explicitly so Streamlit does not attenuate the selected secondary text color.
Initial visual inspection caught stale light input surfaces, clipped metrics
and faint captions; these were corrected before final evidence capture.
